## 🧠 My Problem-Solving Approach

For each problem, I will follow a consistent process:

1. **Understand:** Identify the inputs, expected output, and constraints.
2. **Work through examples:** Solve a small example manually.
3. **Plan:** Write the logic in plain English or pseudocode.
4. **Implement:** Write the Python solution independently.
5. **Test:** Check normal cases, edge cases, and invalid inputs where relevant.
6. **Analyze:** Estimate time and space complexity.
7. **Review:** Record what I learned and revisit difficult problems.

My priority is to understand **why a solution works**, rather than memorizing code or immediately copying an answer.

## 📈 Practice Strategy

I will start with easy problems and gradually move toward intermediate problems as my understanding improves.

- Practise consistently rather than solving many problems in one sitting.
- Attempt problems independently before consulting hints.
- If stuck, break the problem into smaller steps.
- Revisit incorrect solutions and explain the mistake in my own words.
- Reimplement important solutions without looking at previous code.
- Track problem patterns, not just the number of problems solved.

## ⏱️ Complexity Reference

| Complexity | General interpretation |
|---|---|
| \(O(1)\) | Constant time |
| \(O(\log n)\) | Logarithmic time |
| \(O(n)\) | Linear time |
| \(O(n \log n)\) | Common efficient sorting complexity |
| \(O(n^2)\) | Quadratic time |
| \(O(2^n)\) | Exponential time |

These are common growth rates, not guarantees for every algorithm. Actual complexity depends on the algorithm and its implementation.
